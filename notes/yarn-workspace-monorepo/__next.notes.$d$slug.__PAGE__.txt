d:T3dd1,<h2 id="前言">前言</h2>
<p>网上常说的 monorepo，用 yarn workspace 就是一种落地方式。目标很直接：把多个项目里相同的部分抽到一处，少做重复开发，也少在拷贝粘贴里修同一处 bug。</p>
<p>本文按「问题 → 架构对比 → 流行库结构 → 手动搭建 → 依赖合并」拆开说明。</p>
<h2 id="一当前存在的问题">一、当前存在的问题</h2>
<h3 id="1-相同功能组件重复实现">1. 相同功能组件重复实现</h3>
<p>前端里同一个组件常在多个项目里各写一份。人一多、项目一散，更容易变成「同一套 Button / Table / Form，几个人各实现一遍」。靠拷贝共享，组件出问题就得反复复制修补。</p>
<h3 id="2-公共逻辑无法统一管理">2. 公共逻辑无法统一管理</h3>
<p>公司常见 web + app 双端：界面不同，业务逻辑大量重合，却各写一套。后端若是 Node.js + TypeScript，API 类型前后端各定义一遍；表单校验也常是两端各写一份。项目一拆开，公共逻辑就很难统一演进。</p>
<h2 id="二普通项目与-workspace-架构对比">二、普通项目与 workspace 架构对比</h2>
<h3 id="1-普通多项目">1. 普通多项目</h3>
<p>相同逻辑或组件，各自仓库里各存一份：</p>

<p>安装方式可参考 <a href="https://docs.npmjs.com/cli/v6/using-npm/semver">npm 依赖版本说明</a>。版本由 <code>[major, minor, patch]</code> 构成，详见 <a href="https://semver.org/lang/zh-CN/">semver</a>：</p>
<table>
<thead>
<tr>
<th>段</th>
<th>含义</th>
</tr>
</thead>
<tbody>
<tr>
<td>major</td>
<td>不兼容的变更</td>
</tr>
<tr>
<td>minor</td>
<td>兼容的新功能</td>
</tr>
<tr>
<td>patch</td>
<td>兼容的 bug 修复</td>
</tr>
</tbody>
</table>
<p>库若遵循这套规则，只要不 bump major，通常可在同一大版本内合并。默认安装常写成 <code>"dayjs": "^1.11.13"</code>，<code>^</code> 表示会解析到 <code>1.11.13 &#x3C;= dayjs &#x3C; 2.0.0</code>。Yarn 合并依赖时也按这个区间思路处理。</p>
<p>例如：</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="bash" data-theme="ayu-dark"><code data-language="bash" data-theme="ayu-dark" style="display: grid;"><span data-line=""><span style="color:#59C2FF">yarn</span><span style="color:#AAD94C"> workspace</span><span style="color:#AAD94C"> one</span><span style="color:#AAD94C"> add</span><span style="color:#AAD94C"> dayjs@^1.11.13</span></span>
<span data-line=""><span style="color:#59C2FF">yarn</span><span style="color:#AAD94C"> workspace</span><span style="color:#AAD94C"> two</span><span style="color:#AAD94C"> add</span><span style="color:#AAD94C"> dayjs@^1.11.12</span></span></code></pre></figure>
<p>两边都是 caret 范围，有机会合并到同一满足双方的版本。若写成精确版本、去掉 <code>^</code>：</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="bash" data-theme="ayu-dark"><code data-language="bash" data-theme="ayu-dark" style="display: grid;"><span data-line=""><span style="color:#59C2FF">yarn</span><span style="color:#AAD94C"> workspace</span><span style="color:#AAD94C"> one</span><span style="color:#AAD94C"> add</span><span style="color:#AAD94C"> dayjs@1.11.13</span></span>
<span data-line=""><span style="color:#59C2FF">yarn</span><span style="color:#AAD94C"> workspace</span><span style="color:#AAD94C"> two</span><span style="color:#AAD94C"> add</span><span style="color:#AAD94C"> dayjs@1.11.12</span></span></code></pre></figure>
<p>则两个版本会并存，不会合并。</p>
<p>代码没改却突然跑不起来时，除了先核对 Node 版本，也要怀疑依赖区间合并带来的「静默升级」。</p>
<p>其它常见范围写法：</p>
<ol>
<li><code>^</code>：更新 minor / patch；major 为 0 时通常只动 patch；major、minor 都为 0 时更保守。见 <a href="https://docs.npmjs.com/cli/v6/using-npm/semver#caret-ranges-123-062-004">Caret Ranges</a>。</li>
<li><code>~</code>：通常只更新 patch。</li>
<li><code>>=</code>：按规则可落到满足条件的较新版本。</li>
<li>不写符号、写死版本：装指定版本；<code>dayjs@1</code> / <code>dayjs@1.x</code> 一类则落在该 major 的允许区间内。</li>
</ol>
