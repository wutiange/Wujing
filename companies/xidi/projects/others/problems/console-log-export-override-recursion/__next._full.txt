1c:T5aaf,<h2 id="一句话">一句话</h2>
<p><strong>把 <code>console.log</code> 命名导出，再 <code>console.log = () => log()</code> 做全局劫持——Android 上会栈溢出；换成 default export 的 <code>logger.log</code> 就正常。</strong></p>
<h2 id="问题现象">问题现象</h2>
<p>在 <strong>Android WebView / RN 容器</strong>里做日志统一上报：先封装 logger，再全局重写 <code>console.log</code> 走自定义逻辑。</p>

</tr>

<h2 id="根因分析">根因分析</h2>
<h3 id="为什么会递归">为什么会递归？</h3>
<p>劫持的本质是：</p>
<pre><code>新的 console.log  →  自定义逻辑  →  原生 console.log
</code></pre>
<p>写法 A 断裂在最后一环：<strong><code>import { log }</code> 拿到的并不一定是「模块加载那一刻的原生函数」</strong>。</p>
<table>
<thead>
<tr>
<th>原因</th>
<th>说明</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>活绑定 / 桥接方法</strong></td>
<td>Android WebView 里 <code>console.log</code> 可能是宿主桥接方法，提取后调用仍 dispatch 到 <strong><code>console.log</code> 当前槽位</strong></td>
</tr>
<tr>
<td><strong>Bundler 内联</strong></td>
<td>Metro / Webpack 可能把命名导出 <code>log</code> 优化成对全局 <code>console.log</code> 的访问，重写后 import 的 <code>log</code> 与 <code>console.log</code> 同源</td>
</tr>
<tr>
<td><strong>隐式包装</strong></td>
<td>若写成 <code>export const log = (...a) => console.log(...a)</code>（而非直接引用），重写后必递归</td>
</tr>
</tbody>
</table>
<p>一旦 <code>log(...)</code> 内部仍走到<strong>已被重写</strong>的 <code>console.log</code>，调用链闭合：</p>
<pre><code>console.log → wrapper → log → console.log → wrapper → …
</code></pre>

<h2 id="经验总结">经验总结</h2>
<ol>
<li><strong>不要 <code>export const log = console.log</code> 再全局重写 <code>console.log</code></strong>——Android WebView 上极易递归</li>
<li>劫持全局 <code>console.*</code> 时，原生方法必须在模块顶层 <strong><code>const native = console.log.bind(console)</code></strong> 一次性 capture</li>
<li>用 <strong>default export 对象 + 闭包</strong>，不要 export 裸的 console 方法引用</li>
<li>wrapper 函数体内<strong>禁止</strong>再写 <code>console.log(...)</code>，只调 capture 后的 <code>nativeLog</code> 或 <code>logger.log</code></li>
<li>桌面浏览器不一定复现，<strong>以 Android 真机为准</strong>验证日志劫持</li>
</ol>
